# Learning Reflection

> ร่างสำหรับผู้ส่งอ่าน ปรับให้ตรงกับสิ่งที่เรียนรู้จริง และอธิบายได้ด้วยตนเองก่อนส่ง

การพัฒนาจาก notebook ไปเป็น pipeline ทำให้เห็นว่าการได้คำตอบถูกต้องเพียงครั้งเดียวต่างจากการสร้างกระบวนการที่รันซ้ำและตรวจสอบได้อย่างไร การกำหนด schema กลางและเชื่อมข้อมูลพื้นที่ช่วยเพิ่มประโยชน์ของข้อมูล แต่ต้องตรวจว่า join ไม่ทำให้จำนวนเที่ยวเพิ่มขึ้นหรือหายไป การแยก raw snapshot, curated data และ run evidence พร้อมบันทึก hash ทำให้ตรวจย้อนกลับได้ว่าผลแต่ละครั้งมาจากข้อมูลและกฎชุดใด การใช้ cache ช่วยลดงานซ้ำ แต่ต้องออกแบบเงื่อนไขให้ประมวลผลใหม่เมื่อข้อมูลหรือ logic เปลี่ยน ข้อจำกัดที่ยังต้องระวังคือข้อมูลพื้นที่ที่หายไปและการใช้จำนวน trip records ซึ่งไม่สามารถแทนจำนวนผู้โดยสารหรือคุณภาพบริการได้โดยตรง

## AI use และ ownership

งาน Submission 2 นี้ใช้ Codex ช่วยวิเคราะห์ notebook เดิม วางแผน เขียน/ตรวจ code และ tests รัน pipeline และร่างเอกสาร ผู้ส่งควรตรวจทาน source code, กฎ valid, cache key, วิธี join และหลักฐานใน repository รวมถึงปรับ reflection ให้สะท้อนประสบการณ์จริง และสามารถอธิบายหรือแก้ไข code ตามคำถามของผู้สอนได้
